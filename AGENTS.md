# CARLA driving benchmark

This repo measures how coding agents drive closed-loop routes in CARLA. Start with
[the operator handoff](docs/HANDOFF.md) for setup, smoke tests, launching runs, and collecting
scores. See [the design](docs/DESIGN.md) for the daemon and leaderboard integration.

## Choose the right workflow

- **Working on the repo or operating an experiment:** Use this guide and the operator handoff.
  Follow [the first experiments](docs/HANDOFF.md#43-first-experiments) to establish a baseline.
- **Driving interactively with Codex or Claude Code:** Follow
  [the interactive workflow](docs/HANDOFF.md#44-interactive-driving-with-codex-or-claude-code) and
  [the driving guide](docs/OPERATOR_GUIDE.md). Label the run as interactive.
- **Running a scored evaluation:** The operator launches `scripts/run_eval.sh <route> <track> <model>`.
  Select `DRIVER=codex` for the isolated Codex adapter. Claude Code is the default and scripted
  baselines are also available. Use [the benchmark protocol](benchmark/PROTOCOL.md) for run and
  reporting rules and [the Codex setup](docs/HANDOFF.md#45-scored-codex-runs) for adapter details.

## Repo conventions

- Put code executed during a benchmark in `carla_probe/`, setup and launch shell scripts in
  `scripts/`, and offline analysis in `tools/`. Keep `carla_probe/client.py` stdlib-only.
- `carla_probe/agent.py` runs inside the leaderboard process and needs CARLA, leaderboard, and
  scenario_runner. The offline suite uses a fake simulator. With the dev dependencies installed,
  run `python -m pytest`. Re-run the [install checks](docs/HANDOFF.md#3-validate-an-install) on a
  new machine or after changes to `agent.py`, `config.yaml`, or the leaderboard patch.
- Put config knobs in `carla_probe/config.yaml` and read them with `cfg["key"]`. Decide what each
  command or field exposes on `sensors`, `privileged`, and `dense`. Keep the sensors view on
  SENSORS-track inputs. Ground-truth scoring events belong in write-only analysis logs. Extend
  `tests/test_agent_fakesim.py::test_sensors_session` when changing that boundary.
- Every driving command needs `why=`, including an operator `shutdown`. Keep frame conversions
  in `geometry.py`. CARLA world coordinates are left-handed, with y right and yaw clockwise.
  The client-facing ego frame has x forward and y left.
- Change Bench2Drive integration in `patches/bench2drive-0.0.4-probe.patch` and document it in
  `docs/DESIGN.md`. The fetched tree is generated by `scripts/setup_bench2drive.sh`.
  Preserve stock scoring semantics with the patch's environment overrides unset.
- The optional learned policy service runs in `third_party/vla_venv` (Python 3.8 and torch).
  The daemon talks to it over HTTP using the standard library. See `scripts/setup_vla.sh`
  and the fake-service coverage in `tests/test_agent_fakesim.py::test_drive_learned_policy`.
- Keep results, transcripts, and route-specific findings in gitignored `sessions/` or outside
  the repo. Keep Fail2Drive held out from tuning, and keep route XMLs, scenario code, and past
  results out of the evaluated driver's context.
